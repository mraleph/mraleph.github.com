Rules of Isolate Club

  1. You do not talk about Isolate Club
  2. Each thread can enter at most one isolate.
  3. At most one thread can enter specific isolate.
  4. Isolates can't interact directly.

How do Isolates actually run?

  • Isolates created by Isolate.spawn/spawnUri are running on a thread pool managed by Dart runtime
  • Isolates created by the embedder (e.g. Flutter) run where it wants them to run.

                      ─────────────────────────► flutter ui thread #1
                       􀇃UI isolate #1 runs􀇅
                          ─────────────────────► flutter ui thread #2
                           􀇃UI isolate #2 runs􀇅

                    ───────────────────────────► platform (ui) thread
                     􀍯 Many OS APIs are "bound" to this thread.
                     􀍯 That's where platform channels handle messages (by default).

Synchronous interoperability chasm

  • Some APIs are bound to the platform thread.
  • Some APIs can call you back on arbitrary thread.
  • Isolates can't ignore existence of threads if we want better interop.

Crossing the chasm

  • Some APIs are bound to the platform thread.

    ⇒ Bind UI isolate to this thread as well (aka Issue #150525 Merge the platform and UI threads)

💡 Don't use an isolate at all!

Allow thread to enter Isolate Group instead

NativeCallable.isolateGroupBound(callback)

callback executes almost like any other Dart code - but when you try to access global static state you get an exception.

@pragma('vm:shared')

Allow static state to be shared across all isolates in a group - if it does not circumvent isolation boundaries (= no mutable Dart state yet).


                    @pragma('vm:shared') Pointer<SomeStruct> data;

                    void doSomething() {
                      // Spawn 10 native threads all working on the same
                      // data.
                      for (var i = 0; i < 10; i++) {
                        pthread_create(NativeCallable.isolateGroupBound((_) {
                          doSomethingWith(data);
                        }));
                      }
                    }

What about the Web?

  • Ironically dart:isolate support on the Web was removed in Dart 2.0
  • Not enough capabilities to fully replicate Isolate Groups on the Web.
  • We might be able to replicate shared native memory multithreading: JS has SABs
  • Real solution might arrive via WebAssembly's Shared-Everything Threads Proposal
